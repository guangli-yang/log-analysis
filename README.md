## 📖 简介

**Log Analyzer** 是为嵌入式设备固件日志分析场景设计，通过「代码检索 → 模块匹配 → 责任人定位」的核心工作流，帮助研发和测试团队快速从海量日志中定位问题归属。

### 核心价值

| 能力 | 描述 |
|:---|:---|
| 🔍 **快速定位** | 通过关键词匹配，秒级定位日志中的错误行 |
| 🔗 **代码关联** | 将运行时日志与源代码中的日志打印点精确关联 |
| 👤 **责任归属** | 自动匹配模块负责人，一键复制联系方式通知相关人员 |
| 🤖 **AI 辅助** | 调用大模型分析日志，获取专业诊断建议 |
| 📊 **智能分析** | 错误检测、日志过滤、关键片段提取、耗时分析 |
| 🗂️ **项目管理** | 多项目隔离，配置自动持久化，团队协作友好 |

### 🔗 快速分析（日志与代码匹配）

这是 Log Analyzer 的核心功能——将运行时日志中的异常行与源代码日志打印点关联，并自动定位责任人。

```
源代码检索 → 模块日志文件（JSON）
                              ↘
                                快速分析 → 匹配结果 + 责任人清单
                              ↗
模块负责人表（路径→模块→负责人）
```

**使用流程**：

1. **代码检索** → 从源码中提取日志打印语句 → 导出 JSON
2. **导入配置** → 将 JSON 导入到项目 → 存入 `config/<项目>/code-search/`
3. **配置负责人表** → 建立代码路径 → 模块 → 责任人的映射
4. **打开运行时日志** → 点击「快速分析」→ 勾选模块 → 开始匹配
5. **查看结果** → 按负责人分组展示，支持复制结果和联系方式

**支持的日志格式**：

系统自动识别以下三种日志结构模式（按优先级 B → C → A 匹配）：
由于当前可接触的日志格式有限，仅支持三种常见的日志格式，后续会根据实际使用情况逐步扩展。
| 模式 | 格式特征 | 日志行实例 |
|:---|:---|:---|
| **A** | `funcName - [LEVEL]...` | `video_pcie_cancel_process - [ERROR]L649 :[VIDEO] CANCEL` |
| **B** | `[ts][LEVEL] filePath L### funcName():` | `[0:35:50.509][ERROR] module/video/video_pcie.c L649 video_pcie_cancel_process():` |
| **C** | `funcName- filePath L### [MOD][LEVEL]` | `storage_interface_file_dir_access- module/storage/storage_dir.c L32 [HAL][ERROR] --> stat failed` |

**匹配规则详情**：

| 规则 | 说明 |
|:---|:---|
| 日志等级过滤 | 仅 ≥ ERROR 等级进入匹配（ERROR / ERR / FATAL / CRITICAL / ASSERT / PANIC），WARNING / INFO / DEBUG 等一律忽略 |
| 模式A | 仅 funcName 精确匹配（大小写不敏感） |
| 模式B/C | fileName（基本名）+ funcName 双字段精确匹配（大小写不敏感） |
| 行号 | 不参与匹配决策，仅用于结果展示 |
| 文件名 | 仅比较 basename（不含路径），大小写不敏感 |
| 函数名 | 精确匹配（含 `::` 限定名），大小写不敏感 |
| 负责人关联 | 代码文件路径与 `codePath` 做路径段匹配（`/` 边界检查） |
| 匹配策略 | 每行日志取首个命中的候选（单次 find），无启发式猜测 |
| 兜底 | 不满足任何模式的行直接忽略，无内容兜底 |

**不支持的日志格式示例**：

```
❌ [INFO]L88: Data received                 — INFO 等级，被过滤
❌ video_init - [WARN]L200: buffer low      — WARN 等级，被过滤
❌ 无函数名、无文件路径的裸日志行             — 无法匹配任何模式，直接忽略
```

**模块负责人表 — 导入模式**：

| 模式 | 行为 | 适用场景 |

### 🔎 代码日志检索

从源代码中检索日志打印语句，作为快速分析的数据基础。

| 模式 | 原理 | 适用场景 |
|:---|:---|:---|
| **离线模式** | ctags 编译器级解析 + 正则匹配 | 本地源码目录，速度快，无需网络 |
| **在线模式（AI）** | 调用 AI API 智能分析 | 复杂日志模式，需要网络和 API 配置 |

**离线模式特性**：
- ctags 自动提取函数名（覆盖率 100%），降级时回退正则扫描
- 支持自定义检索正则模式（如 `LOGE`、`VIDEO_LOGE` 等）
- 自动提取引号内静态文本，去除 `%s` / `%d` / `\n` / `\t` 等格式占位符
- 结果支持导出 / 导入

**内置检索模式**：

| 模式名称 | 正则表达式 | 说明 |
|:---|:---|:---|
| `LOGE错误` | `LOGE\s*\(\s*"[^"]*"` | 匹配 C/C++ LOGE 宏 |
| `VIDEO_LOGE错误` | `VIDEO_LOGE\s*\(\s*"[^"]*"` | 匹配 VIDEO_LOGE 宏 |

**检索规格与限制**：

| 限制项 | 默认值 | 说明 |
|:---|:---|:---|
| 最大扫描文件数 | 20000 | 超过后不再扫描子目录 |
| 最大结果数 | 50000 | 超过后停止处理，避免内存溢出 |
| 每批并发数 | 20 | 控制磁盘 I/O 压力 |
| ctags 超时 | 60 秒 | 超时自动降级为正则扫描 |
| 大文件阈值 | 10 MB | 超过后跳过 lineOffsets 构建以节省内存 |
| 支持文件类型 | `.c` `.cpp`  | 多语言源码文件 |

**检索结果示例**：

```
📄 代码文件: C:\project\src\video_pipeline.cpp
   行号: 649
   函数: video_pcie_cancel_process
   模式: LOGE错误
   文本: CANCEL
   关键词: [CANCEL]

📄 代码文件: C:\project\src\job_manager.cpp
   行号: 4
   函数: jobRun
   模式: LOGE错误
   文本: Pipeline SNIFFER failed
   关键词: [Pipeline, SNIFFER, failed]
```

### ⏱ 耗时分析（v1.4.0 新增）

分析日志中各节点的时间戳差值，用于性能瓶颈定位。

**使用方式**：
1. 打开分析面板 → 切换到「⏱ 耗时分析」Tab
2. 配置节点关键词列表（第一个节点自动作为轮次起点）
3. 点击「开始分析」
4. 查看各轮次卡片，展开查看详细耗时表格

**支持的日志时间戳格式**：

系统自动匹配行中第一个符合 `[H:MM:SS.mmm]` 格式的方括号：

| 格式 | 日志行实例 | 取哪个方括号 |
|:---|:---|:---|
| **模式A** | `[2026-07-15 10:23:17.372] [0:20:27.064] funcName - [LEVEL]...` | 第2个 `[0:20:27.064]` |
| **模式B** | `[0:35:50.509][LEVEL] filePath L### funcName():...` | 第1个 `[0:35:50.509]` |

> 统一策略：匹配行中第一个 `\d+:\d+:\d+\.\d+` 格式的方括号，该格式在两种模式中唯一，不会与日期或日志等级混淆。

**轮次识别规则**：

| 规则 | 说明 |
|:---|:---|
| 轮次起点 | 用户配置的第一个节点（t1）自动作为轮次起始 |
| 新轮次触发 | 每遇到 t1 即开启新一轮 |
| 首轮前数据 | 第一个 t1 之前的命中数据丢弃 |
| 末轮处理 | 最后一个 t1 之后的不完整轮次保留 |
| 独立计算 | 不同轮次独立计算，互不干扰 |

**输出内容**：

每轮结果包含以下信息：

```
第 1 轮  总耗时: 12.345s

节点        行号      节点时间           区间耗时
开始进纸     L 1523    [0:20:27.064]     —
预打印       L 1560    [0:20:35.820]     8.756s
打印开始     L 1582    [0:20:39.100]     3.280s
打印结束     L 1601    [0:20:39.409]     0.309s
```

| 操作 | 说明 |
|:---|:---|
| 📋 复制全部 | 将所有轮次数据复制到剪贴板 |
| 📄 导出CSV | 导出为 UTF-8 CSV 文件（含 BOM，Excel 友好） |
| 🔄 重新分析 | 清除结果，回到配置状态 |
| 点击行号 | 跳转到日志原文对应行 |

**不完整轮次提示**：若某轮缺少配置中的节点，卡片顶部显示 ⚠ 警告并标注缺少哪些节点。

### 🤖 AI 智能助手

调用 AI 大模型分析日志，获取专业诊断建议。

- 支持配置 API 地址、Key、模型名称，测试连接验证
- 独立浮动窗口，支持拖拽移动，点击外部不关闭
- 一键复制分析结果

**上下文模式**：

| 模式 | 发送内容 | 适用场景 |
|:---|:---|:---|
| **无** | 仅用户问题 | 通用技术咨询 |
| **选中内容** | 日志中选中行 + 用户问题 | 针对特定片段深入分析 |
| **全部日志** | 完整日志内容 + 用户问题 | 全局日志诊断 |
| **最近 N 行** | 末尾 N 行（100 / 200 / 500 / 1000） | 最新问题分析 |

### 📋 日志提取

按条件提取日志片段，生成新的分析文件（写入原文件同目录）：

| 模式 | 说明 | 提取范围 |
|:---|:---|:---|
| **倒数第 N 个作业** | 基于作业关键字，提取指定序号的作业日志段 | 从该作业起始到下一个作业起始（或文件末尾） |
| **最后开机/重启** | 提取系统启动后的日志 | 从最后一次 boot / startup / 开机 / 启动 标记到文件末尾 |
| **最后错误** | 提取最后一个错误前后的日志上下文 | 最后一个错误行的前后 N 行上下文 |
| **自定义关键词** | 按自定义关键词提取相关日志 | 包含关键词的行及其上下文 |

**提取文件命名规则**：`提取_<模式名>_<原文件名>`（如 `提取_最后错误_runtime.log`）

**作业关键字配置示例**：

```
作业关键字：Job Start
作业关键字：Print Job Begin
```

日志中每匹配到一个作业关键字，即标记为一个作业段的开始。输入 `N=2` 则提取倒数第 2 个作业。

## ⚙️ 配置说明

### 项目配置结构

```
config/
└── <项目名>/
    ├── code-search/              # 模块日志目录
    │   ├── video_pipeline.json
    │   ├── job_manager.json
    │   └── ...
    └── module-mapping/           # 模块负责人表
        └── mappings.json
```

### 模块负责人表格式（mappings.json）

```json
{
  "version": "2.0",
  "mappings": [
    {
      "codePath": "project\\video",
      "moduleName": "视频流水线 (VIDEO)",
      "contactName": "张亮",
      "contactInfo": "zhangliang@example.com"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|:---|:---|:---|
| `codePath` | ✅ | 代码文件路径片段，用于路径段匹配 |
| `moduleName` | ✅ | 业务模块名称 |
| `contactName` | ✅ | 模块负责人姓名 |
| `contactInfo` | ❌ | 联系方式（邮箱/电话），填写后支持一键复制 |

### 关键字配置

通过工具栏「⚙️ 关键词设置」管理以下关键字类型：

| 类型 | 用途 | 示例 |
|:---|:---|:---|
| **错误关键字** | 错误分析时匹配日志中的错误 | `print_err`、`copy_err` |
| **作业关键字** | 日志提取时识别作业边界 | `Job Start`、`Job End` |
| **忽略关键字** | 关键词过滤时排除匹配行 | `DEBUG`、`TRACE` |
| **核心转储关键字** | Coredump 分析时匹配 | `coredump`、`SIGSEGV` |
| **代码检索模式** | 离线代码检索的正则表达式 | `LOGE\s*\(\s*"[^"]*"` |

### AI 助手配置

| 配置项 | 说明 | 示例 |
|:---|:---|:---|
| API 地址 | AI 服务端点 | `https://api.openai.com/v1` |
| API Key | 认证密钥 | `sk-xxx...` |
| 模型名称 | 模型标识 | `gpt-3.5-turbo` |

配置通过工具栏「🤖 AI」→ 设置图标 ⚙️ 进入。

## ❓ 常见问题

<details>
<summary><strong>Q: 快速分析提示"请先导入模块映射表"怎么办？</strong></summary>

说明当前项目尚未配置模块负责人表。请在「数据管理」面板中手工添加映射记录，或通过「导入配置」导入 `mappings.json` 文件。
</details>

<details>
<summary><strong>Q: 日志行有匹配但快速分析无结果？</strong></summary>

检查以下几点：
1. 日志等级是否 ≥ ERROR（仅 ERROR / ERR / FATAL / CRITICAL / ASSERT / PANIC 进入匹配，WARNING / INFO 等被忽略）
2. 日志行是否匹配三种结构模式之一（模式A需 `funcName - [LEVEL]`，模式B需 `[ts][LEVEL] filePath L### funcName():`，模式C需 `funcName- filePath L###`）
3. 函数名是否与代码检索结果一致（含 `::` 限定名）
4. 代码检索结果是否已导入到当前项目
</details>

<details>
<summary><strong>Q: 匹配到了但负责人不显示？</strong></summary>

检查模块负责人表中的 `codePath` 是否与代码文件路径的某一层完整路径匹配。例如代码路径 `C:\project\video\pipeline.cpp`，`codePath` 应为 `project\video` 而非 `project`。
</details>

<details>
<summary><strong>Q: 如何配置 AI 助手？</strong></summary>

点击工具栏「🤖 AI」→ 点击设置图标 ⚙️ → 输入 API 地址和 Key → 选择模型 → 点击「测试连接」验证。
</details>

<details>
<summary><strong>Q: 支持哪些日志文件格式？</strong></summary>

`.log` / `.txt` / `.out` / `.err` / `.log.1` / `.log.2` 等，也支持无扩展名的纯文本文件。
</details>

<details>
<summary><strong>Q: 大文件打开很慢怎么办？</strong></summary>

v1.4.0 已针对大文件进行专项滚动性能优化，100MB+ 文件浏览流畅。如遇性能问题，请确保系统有足够内存（建议 4GB+）。
</details>

<details>
<summary><strong>Q: 如何切换研发/测试角色？</strong></summary>

点击「⚙️ 软件设置」→「重置角色」→ 应用重启后显示角色选择界面。

| 角色 | 可用功能 |
|:---|:---|
| 研发 | 全功能（含代码检索、AI 助手、关键词管理、数据管理） |
| 测试 | 日志查看、搜索、快速分析、导入配置 |
</details>

<details>
<summary><strong>Q: 耗时分析的节点怎么配置？</strong></summary>

在分析面板「⏱ 耗时分析」Tab 中直接内联编辑节点关键词列表。第一个节点自动作为轮次起点（t1），遇到 t1 开启新轮次。配置自动保存到本地，重启不丢失。
</details>
